# توجيه تطوير الواجهة (UI/UX) — Furniture Land ERP

> **لمين:** الـ Agent المسؤول عن الواجهة.
> **المطلوب:** نقل الديمو من شكل "Landing Page / Dashboard تسويقي" لشكل **منظومة ERP مؤسسية ضخمة** — هادية، كثيفة المعلومات، متسقة، وتبان إنها اتبنت على Design System واحد.
> **النطاق:** UI و UX فقط. **ممنوع لمس أي لوجيك.**

---

## 0) القواعد الحاكمة (اقراها الأول)

1. **ممنوع تعديل:** `src/services/*` و `src/context/*` و `src/mock/*` و `src/types/*`، وأي حسابات أو Handlers أو أسماء حقول أو Flow بين الشاشات. لو تعديل شكل محتاج تغيير في اللوجيك → **وقف واكتبه في قائمة "يحتاج لوجيك"** وما تنفذوش.
2. **ممنوع حذف أي Feature أو زرار أو شاشة.** ممكن تعيد ترتيبها أو تنقلها لقايمة "إجراءات إضافية (⋯)"، لكن كل وظيفة موجودة لازم تفضل متاحة.
3. **RTL أولاً.** النظام عربي `dir="rtl"`. استخدم الخصائص المنطقية (`ms-/me-/ps-/pe-/start/end`) بدل `left/right` في أي كود جديد.
4. **اشتغل على مراحل** (القسم 9). كل مرحلة لازم تكون قابلة للعرض لوحدها، وما تسيبش الديمو مكسور بين مرحلة والتانية.
5. **بعد كل مرحلة:** شغّل الديمو واتأكد إن السيناريو الأساسي شغال من أوله لآخره (مشروع مطبخ ← عرض سعر ← عقد ← مكتب فني ← تخطيط ← تصنيع ← محاسبة) من غير أي Error في الـ Console.

## 1) التشخيص — الوضع الحالي بالأرقام

ده اللي ظهر من مراجعة الكود والشاشات. **مش لوم، ده خط البداية:**

| المؤشر | الرقم الحالي | المشكلة |
|---|---|---|
| ألوان Hex مكتوبة يدوي (`[#C87A38]` لوحده) | ~1,000 مرة + `[#361D13]` ~525 | مفيش Tokens. أي تعديل في الهوية = Find & Replace في 100 فايل |
| `font-black` | ~1,730 مرة | لما كل حاجة Bold مفيش حاجة مهمة. العين ما بتلاقيش نقطة ارتكاز |
| `text-[10px]` + `text-[11px]` + `text-[9px]` | ~1,220 مرة | خط عربي بحجم 10–11px صعب يتقري على البروجكتور وفي الاجتماع |
| عائلات ألوان مختلفة للحالات (emerald, amber, rose, purple, indigo, blue, teal, cyan, sky, orange…) | 10+ عائلات | "قوس قزح". اللون فقد معناه الدلالي |
| `rounded-3xl` / `rounded-2xl` | ~1,330 مرة | زوايا دايرية جداً = إحساس تطبيق موبايل استهلاكي، مش ERP |
| `bg-gradient` | 111 مرة | تدرجات كتير = إحساس تسويقي |
| صفحات فيها Hero Banner داكن ضخم | ~44 فايل | الـ Banner بياكل ربع الشاشة في كل صفحة قبل ما تشوف أي بيانات |
| مودالات بتتبني كل واحدة لوحدها (`fixed inset-0`) | 75 فايل | مفيش Modal موحد. كل واحد مقاسه وهيدره وأزراره مختلفة |
| `<table>` مكتوبة يدوي | 100 مرة | مفيش Data Table موحد |

### ملاحظات من الشاشات نفسها

- **الـ Sidebar:** كل مجموعة بتفضل مفتوحة لما تفتح غيرها، فالقايمة بتطول جداً. الـ Labels طويلة وفيها عربي + إنجليزي بين قوسين ("دليل وسجل العملاء (Directory)"). الرقم اللي جنب كل مجموعة هو **عدد العناصر**، وده ما يفيدش المستخدم بحاجة. حجم الخط 11px.
- **ازدواج التنقل:** في موديولات زي المشتريات والتخطيط والتصنيع فيه Sidebar **و** شريط Tabs أفقي جوه الصفحة بنفس العناصر، والشريط ده بيعمل Scroll أفقي وشريط Scroll ظاهر.
- **الـ Header مزدحم ومخلوط:** أدوات الديمو (السيناريو، Reset، الدخول كعميل) جنب أدوات المنتج (البحث، الفرع، الإشعارات، المستخدم) بنفس الوزن البصري.
- **كل صفحة شكلها مختلف:** في صفحات بـ Hero داكن، وصفحات بهيدر فاتح، وصفحات بكارت أبيض. مفيش "قالب صفحة" واحد.
- **الجداول:** الصف مش قابل للضغط، وأهم عمود ("لوحة المشروع 360") مستخبي ورا Scroll أفقي. مفيش Sticky Header ولا Pagination ولا اختيار أعمدة ولا Bulk Actions. والمرجع العربي في قيود اليومية مكتوب بخط Monospace فشكله مكسور.
- **التنقل ما بيرجعش لأول الصفحة:** لما تفتح صفحة جديدة بتفتح على نفس مكان الـ Scroll بتاع الصفحة اللي قبلها.
- **صفحة المشروع (360):** مفيش شريط إجراءات واضح فوق. الـ Stepper مكتوب فيه "المرحلة 15 من 18" وهو عارض 8 مراحل بس. والـ Tabs متقسمة على سطرين.
- **لغة الواجهة:** فيها إيموجي (👋)، وعناوين تسويقية طويلة ("منظومة المشتريات وسلاسل الإمداد المتكاملة")، وشارات زي "ENTERPRISE v2.5" و"BI". ده كلام عرض تقديمي، مش كلام نظام تشغيل.

**الخلاصة:** المجهود والعمق الوظيفي كبار جداً، لكن الواجهة **بتصرخ**. الـ ERP الكبير (SAP Fiori، Oracle Redwood، Dynamics 365، Odoo 17) واجهته **هادية ومملة عن قصد**: البيانات هي البطل، واللون بيظهر بس لما يكون له معنى.

## 2) الاتجاه التصميمي — "Calm Enterprise"

### المبادئ (بالترتيب لو حصل تعارض)

1. **البيانات هي البطل.** أول شاشة لازم تبين بيانات حقيقية فوق خط الطي (Above the fold). مفيش Banner بياخد أكتر من 64px ارتفاع.
2. **اللون = معنى.** المحايد (رمادي دافي) هو الأساس. لون البراند للإجراء الأساسي والعنصر النشط بس. أحمر = خطر/متأخر، أخضر = تم/سليم، كهرماني = تحذير/منتظر. وبس.
3. **هرمية واضحة.** حجم واحد كبير في الصفحة (عنوان الصفحة)، والباقي متدرج. الـ Bold للعناوين والأرقام المهمة بس.
4. **الاتساق أهم من الإبداع.** كل جدول زي كل جدول، كل مودال زي كل مودال، كل صفحة سجل زي كل صفحة سجل. المستخدم يتعلم مرة واحدة.
5. **كثافة احترافية.** ERP بيتشاف 8 ساعات في اليوم. مسافات منظمة ومتوسطة، مش هوا كتير ولا زحمة.
6. **الهوية حاضرة بهدوء.** البني والنحاسي (هوية Furniture Land) يفضلوا، لكن كـ "توقيع" مش كـ "خلفية".

### مرجع الإحساس

- **Odoo 17:** في هيكل صفحة السجل (Form View) وشريط الحالة (Status Bar) والـ Chatter.
- **SAP Fiori / Horizon:** في هدوء الألوان والـ Object Page.
- **Linear / Stripe Dashboard:** في نظافة الجداول والطباعة.

**المطلوب إننا نبان "أشيك من Odoo"**، يعني نفس الجدية بس بلمسة دفء وحِرفة تناسب شركة أثاث.

## 3) Design System — الأساس (المرحلة 1، أهم حاجة)

### 3.1 Design Tokens

عرّف كل حاجة كـ **CSS Variables** في `index.css` واربطها في `tailwind.config.js`. **ممنوع Hex مكتوب يدوي في أي Component بعد كده.**

**الألوان (اقتراح، اضبط درجاتها بنفسك مع الحفاظ على الهوية):**

| Token | الاستخدام | قيمة مقترحة |
|---|---|---|
| `--bg-canvas` | خلفية التطبيق | `#F7F5F2` (رمادي دافي خفيف جداً) |
| `--bg-surface` | الكروت والجداول | `#FFFFFF` |
| `--bg-subtle` | Hover، رأس الجدول، الحقول المعطلة | `#F2EFEB` |
| `--border` | كل الحدود | `#E4DED6` |
| `--border-strong` | فواصل مهمة، حقول الإدخال | `#CFC6BB` |
| `--text-primary` | النص الأساسي | `#1F1A17` |
| `--text-secondary` | Labels والوصف | `#5E554E` |
| `--text-muted` | Placeholder وبيانات ثانوية | `#8F857C` |
| `--brand` | الزر الأساسي، العنصر النشط، اللينكات | النحاسي `#B86B2C` (أغمق شوية من الحالي عشان التباين مع الأبيض) |
| `--brand-hover` / `--brand-subtle` | Hover / خلفية العنصر النشط | درجات من نفس اللون |
| `--chrome` | خلفية الـ Sidebar | البني الداكن الحالي `#1E110B` (يفضل) |
| `--success` / `--success-subtle` | تم، معتمد، مُحصّل | أخضر هادي |
| `--warning` / `--warning-subtle` | منتظر، قارب الموعد | كهرماني |
| `--danger` / `--danger-subtle` | متأخر، عجز، مرفوض | أحمر طوبي |
| `--info` / `--info-subtle` | معلومة، قيد التنفيذ | أزرق رمادي هادي |
| `--neutral` / `--neutral-subtle` | مسودة، ملغي، غير نشط | رمادي |

**قاعدة:** مفيش موف ولا فوشيا ولا Teal ولا Cyan ولا Indigo في الحالات. **5 دلالات بس** (success, warning, danger, info, neutral) + البراند.

**الطباعة (Typography):**

- خط واحد: **Cairo** للعربي (أو IBM Plex Sans Arabic لو حبيت إحساس مؤسسي أكتر، والقرار ليك بعد تجربة الاتنين). Tajawal يتشال كـ Fallback ثانوي.
- الأرقام: `font-variant-numeric: tabular-nums` في **كل** الجداول والمبالغ.
- الأكواد (PRJ-2026-001، JE-2026-000106): خط Mono **للكود اللاتيني بس**. **ممنوع النص العربي بخط Mono.**
- السلم (Scale) الوحيد المسموح:

| Token | الحجم | الوزن | الاستخدام |
|---|---|---|---|
| `display` | 24px | 700 | رقم KPI كبير |
| `title` | 20px | 700 | عنوان الصفحة (مرة واحدة في الصفحة) |
| `heading` | 16px | 600 | عنوان Section أو كارت |
| `body` | 14px | 400 | النص الأساسي، خلايا الجداول |
| `body-strong` | 14px | 600 | قيمة مهمة جوه الجدول |
| `label` | 13px | 500 | Labels الحقول، رأس الجدول |
| `caption` | 12px | 400 | بيانات ثانوية، Timestamps |

- **ممنوع أقل من 12px نهائياً.** (حالياً فيه 7px و8px و9px و10px و11px.)
- **`font-black` (900) ممنوع.** أقصى وزن 700، وللعناوين والـ KPIs بس.

**المسافات (Spacing):** سلم 4px: `4, 8, 12, 16, 20, 24, 32, 48`. Padding الكارت 20–24px. المسافة بين Sections في الصفحة 24px.

**الزوايا (Radius):**

| Token | القيمة | الاستخدام |
|---|---|---|
| `radius-sm` | 4px | Badges، Checkbox |
| `radius-md` | 6px | أزرار، حقول إدخال، Tabs |
| `radius-lg` | 10px | كروت، مودالات، Popovers |
| `radius-full` | — | Avatars بس |

**`rounded-2xl` و `rounded-3xl` يتلغوا من التطبيق.**

**الظلال (Elevation):** 3 مستويات بس. الكروت العادية: حد (border) من غير ظل أو ظل خفيف جداً. الـ Dropdowns والـ Popovers: ظل متوسط. المودالات: ظل قوي. **ممنوع `shadow-2xl` و Glow على العناصر العادية.**

**الأيقونات:** Lucide (موجودة). حجم ثابت: 16px جوه الأزرار والجداول، و20px في عناوين الصفحات. اللون يورث لون النص، **مش ملون لوحده**. ممنوع أيقونة ملونة جوه مربع ملون جوه كارت ملون.

**الحركة (Motion):** 150ms ease-out للـ Hover والفتح. احترم `prefers-reduced-motion`. مفيش Animations للزينة.

### 3.2 مكتبة Components موحدة

ابني الـ Components دي في `src/components/ui/`، **وكل الشاشات تستخدمها بعد كده**. كل Component يستخدم الـ Tokens بس.

| Component | المواصفات الأساسية |

| **IconButton** | مربع 32/36px مع Tooltip إجباري. |

| **PageHeader** | (القسم 4.3) |
| **Card / Section** | خلفية بيضا، حد `--border`، `radius-lg`، هيدر اختياري فيه عنوان `heading` + إجراءات على الطرف التاني. |

| **Modal** | مقاسات `sm` 480px، `md` 640px، `lg` 880px. هيدر (عنوان + X)، Body بيعمل Scroll، فوتر ثابت فيه الأزرار (Primary على طرف البداية في RTL). Esc يقفل، والـ Focus Trap شغال. |

| **Toolbar / FilterBar** | بحث + فلاتر (Dropdowns) + Chips للفلاتر النشطة + "مسح الكل" + أزرار العرض. |

| **Timeline / Activity Feed** | للـ Chatter وسجل الأحداث. |

## 4) هيكل التطبيق (App Shell)

### 4.1 الـ Sidebar

- **Accordion حقيقي:** فتح مجموعة يقفل الباقي، والمجموعة النشطة بس مفتوحة افتراضياً.
- **Labels قصيرة وعربي بس:** "العملاء"، "عروض الأسعار"، "العقود"، "أوامر الشراء"، "قيود اليومية". المصطلح الإنجليزي يظهر في Tooltip لو حابب، **مش جوه الـ Label**. أقصى طول تقريباً 3 كلمات.
- **إعادة ترتيب المجموعات حسب رحلة العمل:** الرئيسية ← المبيعات والعملاء ← المكتب الفني ← التخطيط ← المشتريات ← المخازن ← التصنيع والتركيب ← الحسابات ← الإعدادات.
- **الرقم جنب المجموعة:** يتشال، أو يتحول لعدد **مهام تحتاج تدخل** (اعتمادات منتظرة، متأخرات). عدد العناصر ما يتعرضش.
- حجم الخط 14px للمجموعات و13–14px للعناصر. ارتفاع العنصر 36px.
- العنصر النشط: خلفية `brand-subtle` (على الداكن) + شريط رأسي 3px بلون البراند على طرف البداية. **مش كتلة برتقالي مصمت.**
- وضع الـ Collapsed (أيقونات بس): Flyout بيظهر عناصر المجموعة لما تقف على الأيقونة، بدل ما يفرد الـ Sidebar.
- أسفل الـ Sidebar: الإعدادات + المساعدة + زرار الطي.
- شارة "أثاث ومطابخ / جاهز + تفصيل" تتنقل لصفحة إعدادات الشركة، أو تبقى سطر Caption رمادي تحت اللوجو.

### 4.2 الـ Header (Top Bar)

ارتفاع 56px، أبيض، حد سفلي بس. الترتيب (RTL):

- **البداية:** Breadcrumb (الموديول › الصفحة › السجل).
- **الوسط:** **Command Palette** — حقل بحث عريض بـ placeholder "ابحث عن عميل، مشروع، فاتورة…  Ctrl+K". (الشكل والفتح UI، أما نتايج البحث فاستخدم أي بحث موجود فعلاً من غير ما تكتب لوجيك جديد.)
- **النهاية:** مُبدّل الفرع (مضغوط) ← الإشعارات ← اللغة ← المستخدم.

**أدوات الديمو** (السيناريو، إعادة تعيين البيانات، الدخول كعميل، تبديل الشخصية) **تتشال من الـ Header** وتتجمع في واحد من الاتنين دول:

- **Demo Dock:** زرار عائم صغير في الركن (أيقونة 🎬 أو "وضع العرض") بيفتح Panel فيه كل أدوات الديمو، **أو**
- قايمة فرعية جوه قايمة المستخدم بعنوان "أدوات العرض التجريبي".

المهم إن العميل يشوف Header **منتج حقيقي** مش Header ديمو.

### 4.3 قالب الصفحة الموحد (Page Template)

**كل** صفحة في النظام تبدأ بنفس الـ PageHeader:

```
[Breadcrumb صغير]
[عنوان الصفحة 20px]  [سطر وصف 1 اختياري، رمادي، 14px]          [ثانوي] [ثانوي] [⋯]  [＋ إجراء أساسي]
[Tabs الصفحة لو موجودة — Underline]
```

- **الـ Hero Banners الداكنة (حوالي 44 فايل) تتلغي كلها.** المعلومات المفيدة اللي فيها (الفرع، الدور، التاريخ) مكانها الـ Header والـ Breadcrumb أصلاً.
- **الاستثناء الوحيد:** الداشبورد الرئيسية ممكن يبقى فيها سطر ترحيب **صغير** (اسم المستخدم + التاريخ) من غير خلفية داكنة ومن غير إيموجي.
- **Scroll Reset:** أي تنقل لصفحة جديدة يرجّع الـ `main` لأول الصفحة.
- عرض المحتوى: `max-w-7xl` مناسب للداشبوردات. **الجداول والقوايم الكبيرة تاخد العرض كامل** (Fluid) عشان الأعمدة تبان من غير Scroll أفقي.

### 4.4 التنقل جوه الموديول

- **مصدر واحد للتنقل.** لو العنصر موجود في الـ Sidebar، ما يتكررش كـ Tab أفقي في الصفحة. الـ Tabs الأفقية الحالية في (المشتريات، التخطيط، التصنيع) تتشال، والـ Sidebar يبقى هو المرجع.
- الـ Tabs جوه الصفحة تكون لـ **أجزاء نفس الكيان** بس (مثلاً صفحة المشروع: نظرة عامة | المقاسات | التصميمات | التسعير | العقد | المستندات | السجل).

## 5) أنماط الصفحات (Page Archetypes)

كل شاشة في النظام لازم تتصنف تحت نمط من دول وتتبني على قالبه. **ده اللي بيدي إحساس "منظومة واحدة".**

### 5.1 Dashboard (داشبورد موديول)

- صف KPIs (4–6 Tiles بالمواصفات في 3.2).
- تحتهم Grid من 2–3 أعمدة فيه: رسم بياني أو اتنين ← قايمة "يحتاج إجراءك" (اعتمادات، متأخرات) ← آخر النشاطات.
- كل رقم وكل عنصر **قابل للضغط** ويودي للقايمة المفلترة.
- **الرسوم البيانية:** لون واحد (البراند) + درجاته للسلاسل، والدلالي للحالات بس. Gridlines خفيفة. محاور واضحة. Tooltip عند الوقوف.
- ممنوع: كروت بخلفيات ملونة مختلفة، وأيقونات ملونة في مربعات، وتدرجات.

### 5.2 List View (قوائم السجلات) — أهم نمط

الشكل:

```
PageHeader (عنوان + عدد السجلات + زرار إنشاء + تصدير)
Toolbar: [🔍 بحث] [فلتر الحالة ▾] [فلتر الفرع ▾] [المزيد من الفلاتر] · Chips نشطة · [مسح]   |   [عرض: جدول/كانبان] [⚙ الأعمدة]
Saved Views (Tabs صغيرة): الكل · مشاريعي · متأخرة · بانتظار الاعتماد
DataTable
Pagination / عدد السجلات
```

**مواصفات الـ DataTable:**

- **الصف كله قابل للضغط** ويفتح السجل (أو Drawer معاينة). **ده أهم UX Fix في النظام كله.** الأزرار جوه الصف (زي "الملف 360") تتحول لأيقونات تظهر عند الوقوف على الصف أو تتنقل لقايمة ⋯.
- Sticky Header. رأس الجدول: خلفية `bg-subtle`، خط `label` 13px، وزن 500، رمادي.
- ارتفاع الصف: 44px (Comfortable) و 36px (Compact)، ومعاهم Toggle للكثافة.
- Zebra خفيف جداً **أو** فواصل أفقية بس (اختار واحد ونفذه في كل الجداول).
- **محاذاة:** النص للبداية، **الأرقام والمبالغ للنهاية** ومعاها `tabular-nums`، والتواريخ بتنسيق ثابت، والحالة كـ Badge.
- أول عمود = المعرّف (الكود بـ Mono صغير رمادي + الاسم تحته أو جنبه بوزن 600).
- Checkbox للاختيار المتعدد + شريط Bulk Actions يظهر لما يتعمل اختيار.
- ترتيب (Sort) بالضغط على رأس العمود، مع سهم.
- **ممنوع Scroll أفقي إلا لو المستخدم اختار أعمدة كتير.** الأعمدة الافتراضية 6–8 بالكتير، والباقي في "⚙ الأعمدة".
- صف إجماليات (Footer) في الجداول المالية.
- Empty State و Skeleton.
- كل الـ 100 جدول اليدوي يتحولوا للـ Component ده.

**Kanban** (للمشاريع، فرص البيع، أوامر التصنيع): أعمدة بالمراحل، كارت مضغوط (كود، عميل، قيمة، تاريخ، Avatar المسؤول، Badge لو متأخر). نفس البيانات، طريقة عرض تانية.

### 5.3 Record / Form View (صفحة السجل) — نمط Odoo مطوّر

ده المكان اللي العميل هيقارن فيه بـ Odoo مباشرة. الشكل:

```
Breadcrumb: المبيعات › المشاريع › PRJ-2026-001
┌───────────────────────────────────────────────────────────────────┐
│ [PRJ-2026-001] مطبخ رويال مودرن HPL — فيلا النرجس    [Badge الحالة] │
│ العميل · الفرع · المسؤول · القيمة (سطر Meta رمادي)                   │
│                         [ثانوي] [ثانوي] [⋯]   [الإجراء التالي ←]   │
├───────────────────────────────────────────────────────────────────┤
│ Status Bar: الطلب › المعاينة › التصميم › التسعير › العقد › … (Chevron) │
├───────────────────────────────────────────────┬───────────────────┤
│ Tabs: نظرة عامة | المقاسات | التصميمات | …     │  Side Panel:       │
│                                               │  - ملخص مالي        │
│ محتوى الـ Tab (DescriptionList / جداول)         │  - المستندات المرتبطة│
│                                               │  - Chatter/النشاط   │
└───────────────────────────────────────────────┴───────────────────┘
```

- **"الإجراء التالي"** زرار Primary واحد واضح فوق، بيتغير حسب المرحلة (اعتماد التصميم، إصدار العقد، تسليم للمكتب الفني…). **استخدم نفس الـ Handlers الموجودة**، أنت بس بتنقل مكان الزرار.
- **Status Bar** أفقي بشكل Chevron (زي Odoo): المراحل اللي خلصت باللون المحايد الغامق، والحالية بالبراند، واللي جاية رمادي فاتح. **اتأكد إن عدد المراحل في الـ Label يطابق المعروض** (حالياً "15 من 18" مع 8 مراحل ظاهرة). لو المراحل كتيرة اعرض الحالية وجيرانها، والباقي "…".
- **Smart Buttons** (زي Odoo): صف أزرار صغيرة فيها عدادات (عروض الأسعار 2، الفواتير 3، أوامر التصنيع 1، المستندات 5) تودي للسجلات المرتبطة. **ده بيبيّن التكامل بين الموديولات بصرياً، وده كلامنا الأساسي قدام Odoo.**
- **Chatter / Activity Panel** على الجنب: سجل الأحداث والتعليقات والمرفقات بتسلسل زمني.
- الـ Tabs في سطر واحد (لو مش هتكفي: "المزيد ▾").
- "مصفوفة Stage Gates" تبقى Checklist مضغوطة جوه تاب "نظرة عامة" أو في الـ Side Panel، مش Section ضخم.
- وضع العرض (Read) هو الافتراضي، وزرار "تعديل" يحول الحقول لـ Inputs. (لو ده محتاج لوجيك State جديد، سيبه وسجّله في قائمة "يحتاج لوجيك".)

### 5.4 Workspace / Board (لوحات التشغيل: التخطيط، Gantt، MRP)

- الـ Gantt: Timeline أفقي **حقيقي** (محور تواريخ فوق، Bars للمراحل، خط "النهارده"، Bars المتأخرة بالأحمر)، بدل الكروت المرصوصة الحالية. لو التحويل ده محتاج إعادة هيكلة بيانات، اعرض نفس البيانات الموجودة بشكل Timeline من غير ما تغير مصدرها.
- مصفوفة العجز: Heatmap جدولي (الخامة × المشروع) بلون دلالي واحد متدرج.

### 5.5 Shopfloor Kiosk (استثناء مقصود)

- الشاشة دي للتابلت في الورشة، فهي **الاستثناء الوحيد** من الكثافة: أزرار كبيرة (لا تقل عن 56px)، خط كبير، تباين عالي، **ومن غير Sidebar ولا Header** (Full-screen mode بزرار خروج).
- الألوان الدلالية هنا بتبقى أوضح (أخضر "ابدأ"، أحمر "إبلاغ عن تالف").

### 5.6 المستندات المطبوعة (عرض السعر، كارت التشغيل، الملصقات)

- قالب طباعة موحد A4: هيدر (لوجو + بيانات الشركة + الرقم الضريبي)، جدول بنود نظيف، إجماليات واضحة، فوتر (الشروط + التوقيعات + رقم الصفحة).
- أبيض وأسود + لون البراند في الخطوط الفاصلة بس. ده اللي العميل النهائي هيمسكه في إيده، فلازم يبان مستند شركة كبيرة.

### 5.7 Customer Portal

- واجهة منفصلة وأبسط (Consumer-grade). هنا مسموح بلمسة دفء أكتر (صور المشروع، Timeline ودود)، بس بنفس الـ Tokens.

### 5.8 الإعدادات

- Layout بعمودين: قايمة أقسام رأسية على جنب (الشركة، الفروع، المستخدمين، الأدوار، سجل المراجعة، الأمان) والمحتوى جنبها. **بدل صف الـ Pills الحالي.**
- "منصة فحص أمان الـ API" ما تبقاش بلون مختلف عن باقي التابات.

## 6) عرض البيانات (Data Formatting)

| النوع | القاعدة |
|---|---|
| **العملة** | `1,140,000 ج.م` بشكل ثابت في كل النظام. الرقم بـ `tabular-nums`. القيمة السالبة بالأحمر وبين قوسين في الشاشات المالية. |
| **الأرقام** | أرقام لاتينية (0–9) في كل النظام (أدق للمحاسبة وده المتعارف عليه في الـ ERP المصري). فاصل الآلاف إجباري. |
| **التواريخ** | تنسيق واحد في الجداول: `08 أكتوبر 2026` أو `2026-10-08`. **اختار واحد وطبقه في كل مكان.** في السياقات القريبة استخدم "منذ ساعتين" مع Tooltip للتاريخ الكامل. |
| **الأكواد** | `PRJ-2026-001` بخط Mono صغير رمادي، ممكن تتنسخ بالضغط. |
| **النسب** | Progress bar رفيع (4px) + الرقم جنبه. لون البراند، أو دلالي لو فيه حد (Threshold). |
| **الأشخاص** | Avatar صغير + الاسم. |
| **القيم الفاضية** | `—` رمادي، مش "غير محدد" ولا فراغ. |
| **أكواد النظام الخام** | ممنوع تظهر للمستخدم (زي `jrn-sal`). اعرض الاسم العربي. (لو الترجمة محتاجة Mapping موجود في الـ Mock، استخدمه بس في طبقة العرض.) |

## 7) لغة الواجهة (UX Writing)

- **قصير ومباشر.** عناوين الصفحات 1–4 كلمات: "أوامر الشراء"، مش "أوامر الشراء الرسمية (Purchase Orders - PO)".
- **لغة واحدة في كل Label.** المصطلح الإنجليزي (BOM, MRP, GRN) مسموح لو هو المتعارف عليه في الصناعة، لكن من غير ترجمة مكررة بين قوسين.
- **الأزرار = فعل + مفعول:** "إنشاء أمر شراء"، "اعتماد التصميم"، "تسجيل دفعة".
- **ممنوع:** الإيموجي، وكلام التسويق جوه النظام ("منظومة متكاملة"، "ذكاء تشغيلي")، والشارات الوهمية ("ENTERPRISE v2.5"، "BI"، "Live"). الثقة بتيجي من جودة الشغل، مش من الشارات.
- **رسائل الخطأ:** إيه اللي حصل + تعمل إيه. "لا يمكن إصدار العقد: عرض السعر لم يُعتمد بعد. [اعتماد عرض السعر]".
- **التأكيد على الإجراءات الخطيرة:** مودال صغير بيوضح النتيجة، وزرار بلون `danger` عليه اسم الإجراء نفسه ("إلغاء الأمر"، مش "نعم").

## 8) الوصول والجودة (Accessibility & Polish)

- تباين النص ≥ 4.5:1 (WCAG AA)، خصوصاً النص الرمادي والنص على الـ Sidebar الداكن والنحاسي على الأبيض.
- كل عنصر تفاعلي ليه Focus Ring واضح (`outline` بلون البراند).
- التنقل بالكيبورد: Tab بيمشي بترتيب منطقي، Esc يقفل المودالات والقوايم، Enter يفعّل.
- كل IconButton ليه `aria-label` و Tooltip.
- **Responsive:** الهدف الأساسي Desktop (1366 لـ 1920). على 1280 ما يحصلش أي Overflow. والتابلت (1024) يشتغل والـ Sidebar مطوي.
- **وضع العرض (Presentation):** اختبر على 1366×768 بزوم 100%، لأن ده غالباً مقاس البروجكتور في الاجتماع.
- الصور محلية (مش Unsplash) عشان الديمو يشتغل من غير نت. ده Asset مش لوجيك، فهو في النطاق.
- **Dark Mode: مش مطلوب دلوقتي.** بس طالما الـ Tokens معمولة صح، هيبقى ممكن بعدين.

| المرحلة | المحتوى | معيار الانتهاء |
|---|---|---|
| **1. الأساس** | Tokens (الألوان، الخط، المسافات، الزوايا، الظلال) + مكتبة `components/ui` كاملة | الـ Components موجودة ومجربة في صفحة واحدة |

| **4. صفحات السجل** | المشروع 360 ← العميل ← أمر الشراء ← أمر التصنيع ← القيد: بقالب 5.3 (Status Bar + Smart Buttons + Chatter) | صفحة المشروع تبان "Odoo بس أشيك" |

## 11) قائمة "يحتاج لوجيك" (لا تنفذ — سجّل بس)

أي حاجة تكتشفها وإنت شغال ومحتاجة تغيير في البيانات أو الـ State أو الـ Routing، اكتبها هنا وكمّل. أمثلة متوقعة:

- رابط مباشر (Deep link) لكل سجل في الـ URL (حالياً فتح المشروع ما بيغيرش الـ Hash).
- نتايج حقيقية للـ Command Palette عبر كل الموديولات.
- Saved Views وفلاتر محفوظة.
- وضع تعديل/عرض في صفحة السجل لو محتاج State جديد.
- عدادات "مهام تحتاج تدخل" في الـ Sidebar.
- تنسيق التواريخ لو البيانات نفسها متخزنة بأشكال مختلفة.
